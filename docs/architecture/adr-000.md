# ADR-000: Reconcile design contracts before native development

Status: Accepted for planning; implementation and security evidence remain pending.
Date: 2026-10-02

## Context

The documents disagree on package names, event names, delivery stages and when context/budget controls become available. Existing code is engine scaffolding and a regression helper, not a completed native harness. The root is inside a broader Git checkout; repository ownership must be resolved before worktree creation or commits.

## Decision

Use plan.md section 5 for package ownership, AGENTS.md for execution constraints, SYSTEM_DESIGN.md for behavioral contracts, and todo.md for delivery evidence. Canonical event names are ToolCallRequested, PolicyDecision, ToolResult and ToolFailure. Use `verify`, not `verification`; `events` owns append/artifact infrastructure, `task` lifecycle, and `sessions` projections/branching. Owner repositories share an events-owned transaction unit of work for atomic state/event updates; they do not perform independent commits or cross-owner table writes.

Milestones M0–M6 in plan.md/todo.md are the delivery order. Design stages are conceptual groupings. Context assembly, constraint retention, basic compaction and all spend ceilings belong in M1; durable learned memory and active routing remain M5. Complete the native single-agent vertical slice before expanding engines. Retain the root feature inventory until its requirements are mapped; shortening it must preserve normative constraints.

SYSTEM_DESIGN.md section 13 supplies the additional pre-development contracts. Future disagreements stop the affected work and require an ADR plus synchronized documents.

## Alternatives and consequences

Keeping both naming schemes creates duplicate modules and ambiguous audits. Expanding adapters first leaves safety and recovery unproven. A native slice gives one auditable path but delays optional breadth. No new infrastructure, dependency installation or runtime implementation is authorized by this documentation revision.
